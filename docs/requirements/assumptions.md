# 가정 및 해석 결정 (이터레이션 1)

OEM-SWR-001(BL-OEM-1.0)에 없거나 모호한 사항을 공급자가 정한 값이다. 근거를 남기며, OEM 확인이 필요한 항목은 "확인"을 `필요`로 표시한다.
요구사항의 출처 열이 이 문서의 ID를 참조한다.

## 변경 이력

| BL-SWR-0.1 | 2026-11-27 | 초판 작성 (A-01~A-16) | SWR-005~SWR-114 전체 |
| BL-SWR-0.2 | 2026-11-27 | 리뷰 반려 조치: A-02, A-05, A-06, A-09, A-12, A-13, A-15 수정, A-17~A-23 추가 | SWR-005, 007, 008, 013, 101, 105, 106, 120~126 |
| BL-SWR-0.3 | 2026-11-27 | 재리뷰 반려 조치: A-06(DEGRADED에서도 유효한 접근위험 LOCK 적용), A-08 문구, A-23(마이크로초 정수 비교로 변경), A-24 추가 | SWR-005, 013, 101, 104, 106, 108, 122, 125 |

## 가정 목록

| ID | 주제 | 결정 | 근거 | OEM 확인 |
|---|---|---|---|---|
| A-01 | 평가 주기와 시간 | 평가 주기는 **10 ms**다. 시간은 외부에서 `now_s`(초, double)로 주입하며 SW는 시스템 시계를 읽지 않는다. `VehicleSnapshot.timestamp_s`는 이 `now_s`와 같은 값이다. | OEM-NFR-001이 고정 시계 재생을 요구한다. 10 ms이면 300 ms, 100 ms 기준을 각각 30주기, 10주기로 검증할 수 있다. OEM-IF-004는 요청 시각으로 `VehicleSnapshot.timestamp_s`를 쓴다. | 필요 |
| A-02 | 입력 타임스탬프 | 입력 그룹(IF-001, 002, 003, 009)은 각각 `source_timestamp_s`를 가진다. 사양서는 IF-001에만 명시했으나 나머지도 같은 이름과 형식으로 가정한다. | freshness(OEM-SR-003)를 입력별로 판정하려면 입력별 시각이 필요하다. | 필요 |
| A-03 | 필수 입력 | 안전 관련 필수 입력은 IF-001(속도), IF-002(충돌), IF-003(접근위험), IF-009(`ignition_on`, `sensor_fault`)이다. | OEM-SR-003의 "필수 입력"이 목록으로 정의되지 않았다. 이터레이션 1의 판단에 쓰이는 입력만 포함한다. | 필요 |
| A-04 | 충돌 해제 유지 | 충돌 `CONFIRMED`가 확인되면 두 출력은 `RELEASE`로 **래치**되고 `ignition_on`이 FALSE인 평가주기부터 해제된다. 래치 중 운전자의 LOCK 요청과 접근위험은 적용하지 않는다. | OEM-SR-001이 "이후 입력 주기에도 유지"를 요구한다. 충돌 후 탈출 안전을 위해 입력이 사라져도 해제를 유지하는 쪽이 안전하다. 이터레이션 1에서는 래치 해제 후 출력을 규칙 평가 결과로 두며, ignition_off 처리(OFF, 출력 RELEASE)는 SWR-020(이터레이션 2)이다. | 필요 |
| A-05 | 충돌 PENDING | `PENDING`은 그 자체로 출력을 바꾸지 않고, 같은 평가주기의 운전자 요청을 보류하며 이유 `CRASH_PENDING_HOLD`를 기록한다. 접근위험 LOCK(SWR-005)은 계속 적용한다. | IF-002가 `PENDING`을 정의하지만 동작 요구가 없다. 충돌 확정 전에는 불필요한 해제를 피하되 접근위험 잠금은 막지 않는다. | 필요 |
| A-06 | DEGRADED 동작 | 필수 입력이 STALE이거나 INVALID이면 상태는 `DEGRADED`가 되고 새 운전자 요청을 적용하지 않으며, STALE/INVALID 입력에 의존하는 변화는 적용하지 않고 직전 출력을 유지한다. **유효하고 신선한 접근위험 TRUE는 DEGRADED에서도 해당 도어를 LOCK한다.** 충돌 `CONFIRMED` 래치(SWR-007, 120)는 계속 우선한다. | OEM-SR-003은 DEGRADED 상태의 출력을 정의하지 않았다. 입력 신뢰가 없을 때는 출력을 바꾸지 않되, LOCK을 추가하는 접근위험은 OEM-SR-002 수용기준에 따라 계속 적용한다. | 필요 |
| A-07 | sensor_fault | `sensor_fault=TRUE`이면 새 운전자 요청과 접근위험 변화를 적용하지 않고 직전 출력을 유지하며 상태는 `FAULT`다. 유효한 충돌 `CONFIRMED`는 이 규칙보다 우선한다. | OEM-SR-004는 "새 명령을 적용하지 않는다"만 정한다. 충돌 해제(OEM-SR-001)는 "다른 명령보다 우선"이므로 우선한다. | 필요 |
| A-08 | 우선순위 표 | 높은 순서: ① 충돌 CONFIRMED 해제 → ② sensor_fault 유지 → ③ 화재/과온/성인 탑승 해제 → ④ 접근위험 도어별 LOCK/해제 억제 → ⑤ ISOFIX 도어별 LOCK → ⑥ 시동 OFF 해제 → ⑦ 이동 시 자동 잠금 → ⑧ 운전자 명령. 이터레이션 1은 ①, ②, ④, ⑧을 구현하고 ③, ⑤, ⑥, ⑦은 이후 이터레이션에서 같은 판정기에 추가한다. DEGRADED 보류(A-06)는 ⑧ 운전자 명령의 적용 조건이며 ④ 접근위험보다 낮다. | 사양서에 규칙 간 우선순위가 없다. 인명 보호(충돌, 화재 등) 해제를 가장 위에 두고 안전 관련 규칙(ASIL B)을 QM 규칙보다 위에 둔다. | **필요 (핵심)** |
| A-09 | 초기 출력 | 기동 직후 두 출력은 `RELEASE`, 상태는 `NORMAL`이다. OEM-FR-007의 `ignition_on=FALSE` 처리(상태 `OFF`, 이유 `IGNITION_OFF`)는 SWR-020으로 이터레이션 2에서 구현한다. | OEM-FR-007은 SWR-020에 배정되어 있다(OEM 사양서 9장). 이터레이션 1에는 초기 출력만 필요하다. | 필요 |
| A-10 | 상태 복귀 | 모든 필수 입력이 유효하고 신선하며 `sensor_fault=FALSE`인 첫 평가주기에 `NORMAL`로 복귀한다. | 히스테리시스를 두면 사양에 없는 지연이 생긴다. | 필요 |
| A-11 | 형식/범위 오류 | 형식, 범위, enum 오류와 누락은 평가 전에 해당 입력 그룹을 `INVALID`로 표시하고 값은 사용하지 않는다. 필수 입력이 INVALID이면 A-06을 적용한다. | OEM-SR-003, IF 오류 처리 절. | 불필요 |
| A-12 | 접근위험 입력 이상 | 접근위험 입력이 STALE/INVALID이면 출력을 해제하지 않고 직전 값을 유지한다. 접근위험은 필수 입력(A-03)이므로 SWR-122, 125가 이를 적용한다. | 접근위험 불명 상태에서 해제하면 위험하다. | 필요 |
| A-13 | 운전자 요청 (이터레이션 1) | 운전자 요청(`side`, `action`, `source`)은 OEM-FR-001의 부분 구현으로 최하위 우선순위로 수락한다. 등록 `source`는 `physical_button`, `avn`, `voice`, `mobile_app` 4종이다. 4개 경로별 처리 차이, 주행 중 해제 거절(SWR-004), override(SWR-006)는 이터레이션 2에서 다룬다. | 접근위험의 해제 억제(OEM-SR-002) 검증에 해제 요청이 필요하다. IF-004의 값 집합을 사용한다. | 필요 |
| A-14 | SWR-019 | 사양서 추적표에 SWR-019가 없다. "예약(미사용)"으로 두고 OEM 확인 항목으로 둔다. | 번호만 비어 있다. | 필요 |
| A-15 | 부동소수점 | 속도와 시각은 `double`을 쓴다. NaN과 무한대는 INVALID다. 속도 범위 비교는 사양의 부등호를 그대로 따른다. | 사양의 범위가 소수점 값이다. | 불필요 |
| A-16 | 상태/이유코드 | 상태: `NORMAL`, `DEGRADED`, `FAULT`, `OFF`(이터레이션 2에서 사용). 이유코드, 경고코드는 SRS 부록 A에 정의한다. | 사양서에 목록이 없다. | 필요 |
| A-17 | ASIL 상속 | 이터레이션 1은 단일 SW 요소(분할 없음)로 개발한다. ASIL B 안전 요구를 구현하는 SWR-101, 102, 104는 ASIL B로 취급하고, 같은 요소의 QM 요구도 ASIL B 수준의 개발 기준(MC/DC 100%, 정적 분석 예외 없음)을 적용한다. | ASIL 분할(decomposition)과 간섭 배제 증명을 하지 않고 가장 높은 수준을 일괄 적용하는 것이 단순하고 안전하다. | 필요 |
| A-18 | 상태 우선순위 | 상태가 동시에 성립하면 `FAULT` > `DEGRADED` > `NORMAL` 순으로 정한다. 따라서 `sensor_fault=TRUE`와 입력 STALE이 함께 있으면 상태는 `FAULT`다. | 사양서에 상태 간 우선순위가 없다. | 필요 |
| A-19 | 프로젝트 표준 | 제품 코드는 Clang 18 이상, C17, 함수는 반환값 필수·`return` 1회, 빌드 경고 0건을 따른다. 출처는 프로젝트 `CLAUDE.md`다. | 개발 환경 결정(언어 Clang 확정)과 코딩 규칙. | 불필요 |
| A-20 | 동적 메모리 금지 | 제품 코드는 동적 메모리를 사용하지 않는다. 출처는 ISO 26262-6의 권고(ASIL B)다. | 결정론과 메모리 안전을 위해 정적 메모리만 쓴다. | 불필요 |
| A-21 | 경고코드 우선순위 | 경고코드는 한 필드이며 동시에 여러 조건이면 `W_SENSOR_FAULT` > `W_INPUT_INVALID` > `W_INPUT_STALE` 순으로 하나만 낸다. | OEM-SR-003, 004가 경고코드 형식을 정하지 않았다. | 필요 |
| A-22 | 직전 확정 출력 | "직전 확정 출력"은 직전 평가주기에 공개된 두 출력이다. 최초 평가 전 값은 `RELEASE`다. | OEM-SR-004의 용어를 정의한다. | 불필요 |
| A-23 | 입력 나이 | 시각은 마이크로초 정수로 변환해 비교한다: `us(t) = llround(t_s × 1,000,000)`(0.5는 0에서 먼 쪽으로 반올림). 입력 나이는 `age_us = us(now_s) − us(source_timestamp_s)`다. `age_us > 200000`이면 STALE이고 `age_us = 200000`은 신선하다. `age_us < 0`(미래 시각)은 INVALID다. | 부동소수점 경계 오차를 피하고 경계 시험을 결정적으로 만든다. 해상도 1 µs는 사양의 200 ms 기준에 비해 무시할 수 있다. | 필요 |
| A-24 | 이터레이션 1 범위 | OEM-SR-002 검증에 필요한 최소 운전자 요청(OEM-FR-001, OEM-IF-004의 값 집합 검증과 적용)을 이터레이션 1 범위에 포함한다. 그 외 FR-001 상세(4개 경로별 처리, 주행 중 해제 거절)는 이터레이션 2다. | OEM-SR-002 수용기준이 "RELEASE 요청에도 LOCK 유지"를 요구하므로 요청 입력 없이는 검증할 수 없다. | 필요 |
