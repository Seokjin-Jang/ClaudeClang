# 아키텍처 설계 (A-SPICE SWE.2)

## 필수 규칙
1. **컴포넌트를 정의**한다: 책임, 포함 요구사항, 의존 대상을 명시한다.
2. **모든 컴포넌트의 인터페이스를 반드시 정의**한다. 인터페이스 없는 컴포넌트는 허용하지 않는다.
   - 인터페이스 항목: 이름, 제공(provided)/요구(required) 구분, 함수 시그니처, 데이터 타입과 범위, 호출 순서·타이밍, 오류 처리, 반환값 의미
3. **컴포넌트 간 통신은 오직 인터페이스를 통해서만** 한다. 다른 컴포넌트의 내부 함수, 전역 변수, 내부 자료구조에 직접 접근하는 것은 금지한다.
4. **응집도는 높이고 결합도는 낮춘다.**
   - 컴포넌트는 하나의 명확한 책임을 가진다.
   - 의존 방향은 단방향으로 유지하고 순환 의존을 제거한다.
   - 구체 구현이 아니라 추상(인터페이스)에 의존한다.
5. **모듈화, 캡슐화, SOLID**를 준수한다.
   - S: 컴포넌트당 변경 이유는 하나
   - O: 확장에는 열려 있고 수정에는 닫혀 있게
   - L: 대체 가능한 구현은 계약(사전/사후 조건)을 지킨다
   - I: 인터페이스는 클라이언트별로 작게 분리한다
   - D: 상위 컴포넌트가 하위 구현이 아닌 추상에 의존한다

## 동적 동작
정적 구조뿐 아니라 주요 시나리오의 동적 동작(시퀀스, 상태, 자원 사용, 타이밍)도 기술한다.

## 추적성
- SW 요구사항 <-> 컴포넌트 양방향 연결 (매트릭스 갱신)
- 컴포넌트 <-> 인터페이스 <-> 통합 테스트 연결
- 어떤 요구사항에도 매핑되지 않는 컴포넌트가 없어야 하며, 할당되지 않은 요구사항이 없어야 한다.

## 설계 검증 질문
- 컴포넌트를 통째로 교체해도 인터페이스가 같으면 다른 컴포넌트가 영향받지 않는가?
- 컴포넌트의 책임을 한 문장으로 말할 수 있는가? ("그리고"가 들어가면 분리를 검토)
- 의존 관계 그래프에 순환이 있는가?

## 산출물
아키텍처 설계서(컴포넌트 구조도, 인터페이스 명세, 동적 동작, 설계 근거), 추적성 매트릭스. 완료 후 `review` 스킬로 아키텍처 체크리스트 리뷰.
