# 상세 설계 (A-SPICE SWE.3)

## 필수 규칙
1. 컴포넌트를 **모듈로 분해**하고 모듈별 책임, 입력, 출력, 처리 로직, 사용하는 자료구조, 오류 처리를 기술한다.
2. **인터페이스 정의 기준 수준을 설계 시작 시 명시**한다. (예: 컴포넌트 외부에서 호출되는 모듈, 다른 모듈 2개 이상이 사용하는 모듈, 공개 함수를 가진 모듈)
   - 기준 이상의 모듈은 **반드시 인터페이스를 정의**한다. (시그니처, 파라미터 범위, 반환값, 선행/후행 조건)
3. **인터페이스가 정의된 모듈은 오직 그 인터페이스를 통해서만 통신**한다. 내부 함수와 변수는 `static` 등으로 숨긴다.
4. **클린코드 원칙**을 설계에 반영한다.
   - 의도를 드러내는 이름, 작은 함수, 함수당 한 가지 일, 낮은 인자 수
   - 중복 제거(DRY), 부수효과 최소화, 주석 대신 코드로 설명
   - 매직 넘버 대신 이름 있는 상수
5. **단일 책임 원칙(SRP)**: 모듈과 함수는 변경 이유가 하나여야 한다.

## 설계 상세도
구현자가 설계서만 보고 코드를 작성할 수 있고, 단위 테스트 설계자가 설계서만 보고 테스트 케이스를 도출할 수 있는 수준으로 기술한다. 분기 조건, 경계값, 오류 경로를 빠뜨리지 않는다.

## 추적성
- 컴포넌트 <-> 모듈, 모듈 <-> 소스 파일/함수, 모듈 <-> 단위 테스트를 양방향 연결한다.
- 요구사항까지 거슬러 올라가는 연결이 끊기지 않아야 한다.
- 아키텍처와 상세 설계 사이의 불일치(인터페이스 시그니처 등)가 없어야 한다.

## 산출물
상세 설계서(모듈 정의, 인터페이스 명세, 동작 기술), 추적성 매트릭스 갱신. 완료 후 `review` 스킬로 상세 설계 체크리스트 리뷰.
