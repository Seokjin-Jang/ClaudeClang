# 통합 테스트 (A-SPICE SWE.5)

## 원칙
1. **정해진 커버리지 목표를 100% 달성할 때까지 반복**해서 테스트 케이스를 추가한다. 통합 테스트의 커버리지 대상은 아키텍처에 정의된 **인터페이스(함수, 데이터 항목, 호출 순서, 오류 경로)** 이다.
2. Stub/Mock은 필요할 때만 쓰고 **과도하게 의존하지 않는다.** 검증하려는 컴포넌트 쌍은 가능한 한 실제 구현으로 연결한다.
3. **커버리지만을 위한 무의미한 테스트는 금지**한다.
4. **인터페이스 중심**으로 수행한다. 컴포넌트 내부 로직 검증은 단위 테스트의 몫이다.

## 테스트 설계 기준 (아키텍처 설계서에서 도출)
- 각 인터페이스의 정상 호출, 경계값, 무효 입력, 오류 반환 처리
- 호출 순서와 타이밍, 상태 전이를 가로지르는 시나리오
- 컴포넌트 간 데이터 타입, 단위, 범위 불일치
- 여러 컴포넌트를 거치는 요구사항 시나리오
- 기법: **경계값 분석, 동치 클래스, PICT 조합** (`unit-test` 스킬의 [pict-example.md](../unit-test/pict-example.md) 참고)

## Doxygen 주석 (모든 테스트 함수 필수)
테스트 목적, 입력값, 절차, 예상 출력값을 적는다. 추가로 대상 인터페이스와 연동 컴포넌트를 명시한다.

```c
/**
 * @test      ITC_SPEED_BRAKE_001
 * @brief     [목적] SpeedCtrl이 BrakeCtrl 인터페이스로 제동 요청을 전달하는지 확인
 * @interface IF_BRAKE_REQUEST (SpeedCtrl -> BrakeCtrl)
 * @requirement SWR-021
 * @input     현재 속도 = 121 (제한 120)
 * @procedure 1. 두 컴포넌트를 실제 구현으로 연결해 초기화한다.
 *            2. SpeedCtrl에 속도 121을 입력한다.
 *            3. BrakeCtrl이 수신한 요청을 확인한다.
 * @expected  BrakeCtrl이 BRAKE_ON 요청 1회를 수신
 */
void test_speed_brake_request(void) { ... }
```

## 추적성
통합 테스트 <-> 아키텍처 컴포넌트/인터페이스 <-> 요구사항을 양방향 연결하고, 결과와 커버리지를 기록한다. 완료 후 `review` 스킬로 통합 테스트 체크리스트 리뷰.
